  Phase 6 — Models as a Service (MaaS)
══════════════════════════════════════════════════════════════

Goal:     Deploy the MaaS gateway, configure Authorino TLS,
          bootstrap subscriptions, and verify API key creation.
Time:     ~10-15 min

RHOAI 3.5 changes:
  - MaaS infra namespace: redhat-ai-gateway-infra (was redhat-ods-applications)
  - DSC field: aigateway.modelsAsAService (was kserve.modelsAsService)
  - Tenant CR is a deprecated no-op shim; Config/AITenant/MaasTenantConfig
    auto-bootstrap on modelsAsService=true — nothing to apply manually
  - Body-based model routing supported (/v1/chat/completions with model name)

Order matters:
  1. Deploy MaaS gateway
     ⚠ allowedRoutes must include redhat-ai-gateway-infra
  2. Configure database (maas-db-config secret in redhat-ai-gateway-infra)
  3. Enable modelsAsService=true (re-apply RHOAI instance)
  4. Configure Authorino TLS for MaaS
     ⚠ Without Authorino TLS, API key endpoint returns 500
     ⚠ Race condition: steps 4a-4c must complete before 4d
  5. Verify auto-bootstrapped AITenant/MaasTenantConfig/maas-api
     ⚠ Do NOT create a Tenant CR — it's a no-op compatibility shim
  6. Deploy or publish a model for MaaS
     (publish existing Phase 5 model OR deploy a new one)
  7. Bootstrap subscription stack (MaaSSubscription + MaaSAuthPolicy)
  8. Enable dashboard flags + verify API key creation

Human gate:
  - LLMInferenceService shows Ready: True
  - API key creation returns sk-oai-* key
  - MaaS dashboard accessible

Guide: docs/phases/06-maas.md
