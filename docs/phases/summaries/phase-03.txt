  Phase 3 — Core Operators + RHOAI
══════════════════════════════════════════════════════════════

Goal:     Install Connectivity Link, LeaderWorkerSet, monitoring
          operators (Tempo, OpenTelemetry), and RHOAI.
          Configure DataScienceCluster.
Time:     ~20-30 min

Install method by operator:
  OLMv1 (cluster-extension.yaml on 4.21+, operator.yaml on 4.20):
    Connectivity Link
  OLMv0 only (always use operator.yaml / oc apply -k):
    LeaderWorkerSet (bundle doesn't support AllNamespaces)
    Tempo (RHOAI detects via CSV only)
    OpenTelemetry (RHOAI detects via CSV only)
  Helm (--set olmVersion=v1 on 4.21+):
    RHOAI

  1. Connectivity Link → wait for operator ready
     → Create Kuadrant CR (Authorino + Limitador)
     ℹ RHCL 1.3.5+ required; pin v1.3.6 + Manual InstallPlan approval
     ℹ Use ./scripts/approve-rhcl-installplan.sh (never bulk-approve openshift-operators)
     ⚠ Kuadrant Ready=False is EXPECTED (no GatewayClass yet)
  2. LeaderWorkerSet (always OLMv0) → wait CRD
  3. Tempo + OpenTelemetry (always OLMv0) → wait CSVs Succeeded
     ⚠ Must be installed BEFORE RHOAI
  4. RHOAI operator → ask user: stable or ea
     → wait for operator ready
  5. RHOAI instance (DSCi + DSC) → two-pass apply
     → wait LLMInferenceService CRD + controller pods

DO NOT: install Kueue, set modelsAsService=true, install
        Service Mesh 2.x or Serverless

Human gate:
  - ./scripts/check-operators.sh — all required Succeeded
  - Controller pods running in redhat-ods-applications

Guide: docs/phases/03-operators-rhoai.md
